About the catalog

A free, community-run collection of script packages for OpsKit, the PowerShell terminal toolkit for system administrators.

What is OpsKit?

OpsKit is an open-source PowerShell 7.4+ toolkit that puts your admin scripts behind a fast keyboard-driven terminal menu. Scripts become menu entries, their parameters become prompts, and their output becomes tables you can export. You add scripts by dropping folders into it.

This catalog is where those folders are shared. Each package is one folder and becomes one OpsKit menu entry.

Why is everything free?

Admins have been sharing scripts for as long as there have been admins. The catalog just makes them easier to find, read and install. Every package is MIT licensed, the site is static on GitHub Pages, and there's nothing to sell: no accounts, ratings, comments, analytics, tracking or cookies.

Safety model

Community scripts run with your permissions. Read the code before running it, and try it somewhere safe first.

What the catalog does to keep packages trustworthy:

  • Everything is readable. Packages may only contain .ps1, .psd1 and .md files, at most 256 KB. No binaries. Every file is shown on the package page, exactly as it is in the zip.
  • Automated checks. CI parses every script, runs PSScriptAnalyzer and rejects patterns that hide or fetch code (Invoke-Expression, encoded commands, base64 payloads, download-and-run), weaken security tools, contain hard-coded secrets, or persist through profiles and startup locations.
  • Human review. A maintainer reviews every pull request that touches packages/. Exceptions to the banned patterns need a written reason and a maintainer's approval.
  • Metadata is never executed. The build reads $ScriptInfo from the PowerShell syntax tree. No package code runs during the build.
  • Checksums. Each zip's SHA-256 is published in catalog.json and on the package page.

What it can't do: automated checks and review reduce risk, they don't remove it. A script that deletes users is doing its job. Read what it does before you run it. If something looks wrong, use Report a problem on the package page.

Licence

The catalog and every package in it are released under the MIT licence. By submitting a package you agree to license it under MIT.

FAQ

How do I install a package?

Download the zip from its package page and extract it into your OpsKit Custom/ folder, so the package folder sits directly inside it. Restart OpsKit. Installing from inside OpsKit (Catalog › Install) is coming.

How do I update a package?

Download the new zip and extract it over the old folder. The version number is in module.psd1 and on the package page.

Can tools other than OpsKit read the catalog?

Yes. catalog.json lists every package with its scripts, parameters, download URL and SHA-256. The format is versioned and described by a JSON Schema.

Does the site track me?

No. It's static files on GitHub Pages with no analytics, cookies or third-party requests. Your theme choice is saved in your browser's local storage and never leaves it. GitHub may keep its own server logs; see GitHub's privacy statement.

A script did something bad. What now?

Open a problem report. For anything that looks malicious, say so in the title and a maintainer will pull the package first and investigate after.

Can I sell scripts here, or link to paid ones?

No. Everything in the catalog is free and MIT licensed, and scripts must work without a paid add-on from the author.
